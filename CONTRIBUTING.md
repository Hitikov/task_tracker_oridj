# Как внести вклад в Arij

## Ветки

- `feature/stage-N-краткое-описание` — основная ветка этапа, создаётся от
  актуального `main`.
- `agent/stage-0-...` — ветки агентов этапа 0; вливаются в ветку этапа после
  ревью.
- Одна задача — одна ветка. Не коммитьте напрямую в `main`.

## Коммиты

- Заголовок короткий и императивный, до ~72 символов:
  `feat: добавить экран проекта`, `fix: исправить валидацию`, `docs: обновить README`.
- Тело коммита — по необходимости: что изменилось и почему.
- Не смешивайте в одном коммите несвязанные изменения.

## Перед PR

Клиент (из корня репозитория):

```powershell
dart format lib test
flutter analyze
flutter test
```

Сервер (из каталога `server/`):

```powershell
dart format .
dart analyze
dart test
```

## Pull request checklist

- [ ] Тесты добавлены или обновлены и проходят;
- [ ] Код отформатирован (`dart format`);
- [ ] В изменениях нет секретов: `.env`, паролей, токенов и ключей;
- [ ] Документация обновлена (README, `docs/`, при необходимости — ROADMAP);
- [ ] CI зелёный, PR содержит понятное описание и ссылку на issue.

## Секреты

`.env` и `.env.local` не коммитятся. Локальные значения храните только в
переменных окружения; в репозитории должен лежать безопасный пример
конфигурации (`.env.example`).
