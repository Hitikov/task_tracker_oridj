# Приложение Б. Сценарии использования основных функций

## Б.1. Регистрация пользователя

### Назначение

Сценарий описывает процесс создания новой учетной записи пользователя в программном обеспечении «Arij».

### Предусловия

- Пользователь не имеет учетной записи в программном обеспечении.
- Пользователь находится на странице регистрации.

### Основной сценарий

1. Пользователь открывает форму регистрации.
2. Пользователь вводит необходимые регистрационные данные.
3. Пользователь отправляет заполненную форму.
4. Программное обеспечение проверяет корректность введенных данных.
5. Программное обеспечение проверяет отсутствие учетной записи с указанными регистрационными данными.
6. Программное обеспечение создает новую учетную запись.
7. Пользователю автоматически присваивается уникальный идентификатор.
8. Программное обеспечение сообщает об успешном завершении регистрации.

### Альтернативные сценарии

- Если обязательные данные не заполнены, программное обеспечение сообщает об ошибке и предлагает заполнить отсутствующие данные.
- Если введенные данные имеют некорректный формат, программное обеспечение сообщает об ошибке.
- Если учетная запись с указанными данными уже существует, программное обеспечение сообщает об этом и не создает новую учетную запись.

### Результат

В программном обеспечении создана учетная запись пользователя с уникальным идентификатором.

## Б.2. Аутентификация пользователя

### Назначение

Сценарий описывает процесс входа зарегистрированного пользователя в программное обеспечение.

### Предусловия

- Пользователь зарегистрирован в программном обеспечении.
- Пользователь находится на странице аутентификации.

### Основной сценарий

1. Пользователь вводит данные для входа.
2. Пользователь отправляет форму аутентификации.
3. Программное обеспечение проверяет введенные данные.
4. Программное обеспечение идентифицирует пользователя.
5. Программное обеспечение выполняет аутентификацию пользователя.
6. Программное обеспечение предоставляет пользователю доступ к доступным ему функциям и проектам.

### Альтернативные сценарии

- Если данные для входа введены некорректно, программное обеспечение сообщает об ошибке.
- Если учетная запись не существует, программное обеспечение сообщает об ошибке аутентификации.
- Если пользователь не прошел аутентификацию, доступ к защищенным функциям программного обеспечения не предоставляется.

### Результат

Пользователь успешно аутентифицирован и получает доступ к разрешенным ему функциям программного обеспечения.

## Б.3. Создание проекта

### Назначение

Сценарий описывает процесс создания нового проекта пользователем.

### Предусловия

- Пользователь успешно аутентифицирован.
- Пользователь обладает правами на создание проекта.

### Основной сценарий

1. Пользователь открывает раздел управления проектами.
2. Пользователь выбирает функцию создания проекта.
3. Программное обеспечение отображает форму создания проекта.
4. Пользователь вводит необходимые параметры проекта.
5. Пользователь подтверждает создание проекта.
6. Программное обеспечение проверяет корректность введенных данных.
7. Программное обеспечение создает новый проект.
8. Программное обеспечение добавляет пользователя, создавшего проект, в состав участников проекта.
9. Программное обеспечение предоставляет пользователю доступ к созданному проекту.

### Альтернативные сценарии

- Если обязательные данные не заполнены, программное обеспечение сообщает об ошибке.
- Если данные проекта имеют некорректный формат, программное обеспечение сообщает об ошибке и не создает проект.

### Результат

Создан новый проект, доступный пользователю.

## Б.4. Добавление участника в проект и назначение роли

### Назначение

Сценарий описывает процесс добавления зарегистрированного пользователя в проект и назначения ему роли.

### Предусловия

- Пользователь успешно аутентифицирован.
- Пользователь имеет права на управление составом участников проекта.
- Проект существует.
- Добавляемый пользователь зарегистрирован в программном обеспечении.

### Основной сценарий

1. Пользователь открывает проект.
2. Пользователь открывает раздел управления участниками проекта.
3. Пользователь выбирает функцию добавления участника.
4. Пользователь вводит уникальный идентификатор добавляемого пользователя.
5. Программное обеспечение выполняет поиск пользователя по указанному идентификатору.
6. Программное обеспечение отображает найденного пользователя.
7. Пользователь выбирает роль для добавляемого участника.
8. Пользователь подтверждает добавление участника.
9. Программное обеспечение добавляет пользователя в состав участников проекта.
10. Программное обеспечение сохраняет назначенную роль.
11. Программное обеспечение предоставляет участнику доступ к функциям проекта в соответствии с назначенной ролью.

### Альтернативные сценарии

- Если пользователь с указанным идентификатором не найден, программное обеспечение сообщает об ошибке.
- Если пользователь уже является участником проекта, программное обеспечение сообщает об этом.
- Если роль не выбрана, программное обеспечение не позволяет завершить операцию.
- Если текущий пользователь не обладает необходимыми правами, операция не выполняется.

### Результат

Пользователь добавлен в проект и ему назначена роль.

## Б.5. Создание задачи

### Назначение

Сценарий описывает процесс создания новой задачи в проекте.

### Предусловия

- Пользователь успешно аутентифицирован.
- Пользователь имеет доступ к проекту.
- Пользователь обладает правами на создание задач.

### Основной сценарий

1. Пользователь открывает проект.
2. Пользователь выбирает функцию создания задачи.
3. Программное обеспечение отображает форму создания задачи.
4. Пользователь вводит название задачи.
5. Пользователь при необходимости вводит описание.
6. Пользователь выбирает тип задачи.
7. Пользователь выбирает приоритет.
8. Пользователь при необходимости назначает исполнителя.
9. Пользователь при необходимости устанавливает дедлайн.
10. Пользователь подтверждает создание задачи.
11. Программное обеспечение проверяет корректность введенных данных.
12. Программное обеспечение автоматически формирует уникальный идентификатор задачи.
13. Программное обеспечение создает и сохраняет задачу.
14. Программное обеспечение отображает созданную задачу.

### Альтернативные сценарии

- Если название задачи не указано, программное обеспечение сообщает об ошибке.
- Если введенные данные некорректны, программное обеспечение сообщает об ошибке и не создает задачу.
- Если исполнитель или дедлайн не указаны, задача создается без соответствующих значений.

### Результат

В проекте создана новая задача с уникальным идентификатором.

## Б.6. Создание иерархии «Эпик → Задача → Подзадача»

### Назначение

Сценарий описывает создание иерархической структуры задач в проекте.

### Предусловия

- Пользователь успешно аутентифицирован.
- Пользователь имеет доступ к проекту.
- Пользователь обладает необходимыми правами на создание задач.

### Основной сценарий

1. Пользователь открывает проект.
2. Пользователь создает эпик.
3. Программное обеспечение сохраняет эпик в проекте.
4. Пользователь создает задачу.
5. Пользователь указывает созданный эпик в качестве родительского элемента задачи.
6. Программное обеспечение сохраняет задачу в составе выбранного эпика.
7. Пользователь создает подзадачу.
8. Пользователь указывает задачу в качестве родительского элемента подзадачи.
9. Программное обеспечение сохраняет подзадачу в составе выбранной задачи.
10. Программное обеспечение отображает сформированную иерархию.

### Альтернативные сценарии

- Если родительский элемент не выбран, элемент создается без соответствующего родителя, если это допускается правилами проекта.
- Если пользователь не имеет необходимых прав, операция создания соответствующего элемента не выполняется.
- Если указанный родительский элемент недоступен или не существует, программное обеспечение сообщает об ошибке.

### Результат

В проекте сформирована иерархия:

**Эпик → Задача → Подзадача**.

## Б.7. Изменение статуса задачи

### Назначение

Сценарий описывает изменение текущего статуса задачи в соответствии с настроенным workflow проекта.

### Предусловия

- Пользователь успешно аутентифицирован.
- Пользователь имеет доступ к задаче.
- Пользователь обладает правами на изменение статуса.
- Для проекта настроен workflow.

### Основной сценарий

1. Пользователь открывает задачу.
2. Пользователь выбирает новый статус.
3. Программное обеспечение проверяет возможность перехода из текущего статуса в выбранный.
4. Программное обеспечение изменяет статус задачи.
5. Программное обеспечение сохраняет изменение.
6. Программное обеспечение фиксирует изменение статуса в истории.
7. Программное обеспечение отображает новый статус задачи.

### Альтернативные сценарии

- Если выбранный переход не предусмотрен workflow, программное обеспечение не изменяет статус и сообщает об ошибке.
- Если пользователь не имеет права изменять статус, операция не выполняется.
- При ошибке сохранения новый статус не применяется.

### Результат

Задача переведена в новый статус, а изменение сохранено в истории.


---

## Б.8. Работа с задачей через Kanban

### Назначение

Сценарий описывает изменение статуса задачи посредством перемещения ее карточки между колонками Kanban.

### Предусловия

- Пользователь успешно аутентифицирован.
- Пользователь имеет доступ к проекту.
- Пользователь обладает правами на изменение статуса задачи.
- В проекте настроены статусы.
- Открыто представление Kanban.

### Основной сценарий

1. Пользователь открывает представление Kanban.
2. Программное обеспечение отображает задачи проекта в соответствующих колонках статусов.
3. Пользователь выбирает карточку задачи.
4. Пользователь перемещает карточку в другую колонку.
5. Программное обеспечение определяет новый статус задачи.
6. Программное обеспечение проверяет допустимость перехода согласно workflow.
7. Программное обеспечение изменяет статус задачи.
8. Программное обеспечение сохраняет изменение.
9. Программное обеспечение отображает карточку задачи в новой колонке.

### Альтернативные сценарии

- Если переход между выбранными статусами запрещен workflow, задача не перемещается, а программное обеспечение сообщает об ошибке.
- Если пользователь не имеет права изменять статус, операция не выполняется.
- При ошибке сохранения задача возвращается в исходное состояние.

### Результат

Статус задачи изменен посредством Kanban, а изменение сохранено в программном обеспечении.

## Б.9. Просмотр задач в Backlog

### Назначение

Сценарий описывает просмотр задач проекта в представлении Backlog.

### Предусловия

- Пользователь успешно аутентифицирован.
- Пользователь имеет доступ к проекту.
- В проекте существуют задачи.

### Основной сценарий

1. Пользователь открывает проект.
2. Пользователь выбирает представление Backlog.
3. Программное обеспечение получает задачи проекта.
4. Программное обеспечение отображает список задач.
5. Для каждой задачи отображаются основные сведения:
    - название;
    - статус;
    - дедлайн;
    - исполнитель;
    - приоритет.
6. Пользователь при необходимости изменяет порядок сортировки задач.
7. Программное обеспечение обновляет порядок отображения задач.

### Альтернативные сценарии

- Если в проекте отсутствуют задачи, программное обеспечение отображает пустой Backlog.
- Если пользователь не имеет доступа к проекту, задачи проекта не отображаются.

### Результат

Пользователь получает список задач проекта в представлении Backlog.

## Б.10. Просмотр отчета

### Назначение

Сценарий описывает просмотр пользователем заранее определенного отчета с аналитической информацией о задачах проекта.

### Предусловия

- Пользователь успешно аутентифицирован.
- Пользователь имеет доступ к проекту.
- Для программного обеспечения определен соответствующий набор отчетов.

### Основной сценарий

1. Пользователь открывает раздел отчетов.
2. Программное обеспечение получает необходимые данные по задачам проекта.
3. Программное обеспечение рассчитывает показатели, предусмотренные соответствующим отчетом.
4. Программное обеспечение формирует представление отчета на основе заранее заданной структуры.
5. Программное обеспечение отображает отчет пользователю.
6. Пользователь просматривает представленные показатели и диаграммы.

### Альтернативные сценарии

- Если для выбранного проекта отсутствуют данные для построения отчета, программное обеспечение отображает отчет без соответствующих данных.
- Если произошла ошибка получения данных, программное обеспечение сообщает об ошибке.

### Результат

Пользователь просматривает заранее определенный отчет с аналитической информацией о проекте.
