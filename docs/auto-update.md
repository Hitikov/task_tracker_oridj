# Автоматическое обновление Arij

Приложение само проверяет GitHub Releases, скачивает подходящий файл и запускает
установку. Ручная кнопка «Проверить обновления» использует тот же поток.

## Как это работает

1. При старте (только в release-сборке) и затем каждые 6 часов
   `UpdateController` запрашивает `GET /api.github.com/repos/Hitikov/task_tracker_oridj/releases/latest`.
2. Версия из тега сравнивается с `PackageInfo.version`. Prerelease-релизы
   игнорируются.
3. Для Windows выбирается ассет `.exe`, для Android — `.apk`. На других
   платформах автоустановки нет — открывается страница релиза.
4. Файл скачивается во временную папку `arij_updates` и сверяется по SHA256 из
   `SHA256SUMS.txt` того же релиза. При расхождении установка отменяется.
5. Установка:
   - **Windows:** `ArijSetup-*.exe` запускается с `/VERYSILENT /NORESTART
     /CLOSEAPPLICATIONS /RESTARTAPPLICATIONS`. Установщик использует
     `PrivilegesRequired=lowest` и `%LOCALAPPDATA%`, поэтому UAC не требуется;
     приложение закрывается и открывается заново.
   - **Android:** APK открывается через FileProvider (`open_filex`) — систему
     установки подтверждает пользователь. Android не разрешает тихую установку
     сторонних APK, поэтому один тап неизбежен.
   - **Остальные платформы:** показывается диалог со ссылкой на релиз.

Код: [update_controller.dart](../lib/updates/update_controller.dart),
[update_service.dart](../lib/updates/update_service.dart),
[update_downloader.dart](../lib/updates/update_downloader.dart),
[update_installer.dart](../lib/updates/update_installer.dart).

## Обязательные условия обновления Android

Без этих двух условий Android покажет «Приложение не установлено» и потребует
удаления старой версии:

1. **Стабильная подпись.** Все релизы должны подписываться одним keystore.
   Секреты `ANDROID_KEYSTORE_*` описаны в [ci-cd.md](ci-cd.md). Сборки с
   debug-подписью имеют разный ключ на каждом запуске CI и не обновляются
   поверх предыдущих.
2. **Возрастающий `versionCode`.** Это число после `+` в `pubspec.yaml`.
   Старые релизы имели `+0`; версия с автообновлением — `2.0.4+5`. Каждый следующий релиз
   должен увеличивать его.

⚠️ Переход с debug-подписи на стабильный ключ меняет подпись приложения.
Однократно удалите старую версию и установите новую. Все последующие обновления
будут ставиться поверх без удаления.

`applicationId` сознательно оставлен `com.example.task_tracker_oridj`: его
изменение также сделает новую сборку «другим приложением» и снова потребует
переустановки. Менять его можно только с пониманием этого последствия.

## Проверка перед релизом

```powershell
# Подпись APK (должна быть одинаковой у двух последовательных сборок)
apksigner verify --print-certs dist/task_tracker_oridj-2.0.4-android.apk

# versionCode / versionName
aapt dump badging dist/task_tracker_oridj-2.0.4-android.apk | Select-String 'versionCode|versionName'

# Состав релиза: обязаны быть .apk, .exe и SHA256SUMS.txt
```

Windows: установите предыдущую версию через `ArijSetup-*.exe`, опубликуйте
новый релиз с увеличенной версией, откройте приложение — должно появиться
обновление без запуска установщика вручную.

Android: установите подписанный release-APK, опубликуйте следующий релиз с
большим `versionCode`, откройте приложение — после скачивания откроется системный
диалог установки; подтверждение установит новую версию поверх старой.

## Ограничения

- На Android пользователь всё равно подтверждает установку системой.
- `REQUEST_INSTALL_PACKAGES` может потребовать включения «Установка
  неизвестных приложений» в настройках Android (система предложит это сама).
- Проверка обновлений требует интернета; сетевые ошибки молча игнорируются.
- Отладочные сборки (`kDebugMode`) автообновление не запускают.
- Windows-архив `.zip` (портативная сборка) не обновляется автоматически:
  автообновление работает только с установщиком `.exe`.
